# P2P-сеть ISOTOPE

## Обзор

P2P-сеть ISOTOPE построена на **libp2p** — модульном сетевом стеке, разработанном Protocol Labs (IPFS, Filecoin).

Сеть не имеет серверов. Каждый узел равноправен.

---

## Архитектура сети

### Транспортный уровень

| Транспорт | Назначение | Статус |
|-----------|------------|--------|
| **TCP** | Основной транспорт | Работает |
| **WebSocket + TLS** | Маскировка под HTTPS, обход DPI | Работает (WS 9001 блокируется провайдером Городок) |
| **mDNS** | Обнаружение в локальной сети | Работает |
| **Bluetooth** | Связь без интернета | В планах |
| **Wi-Fi Direct** | Прямое соединение без роутера | В планах |

### Обнаружение пиров

| Механизм | Область | Статус |
|----------|---------|--------|
| **mDNS** | Локальная сеть | Работает |
| **DHT Kademlia** | Глобальная сеть (WAN) | В планах (15+ узлов) |
| **Bootstrap-узлы** | Первый вход в сеть | VPS ISOTOPE (bootstrap) |

### Синхронизация слоёв

| Механизм | Описание | Статус |
|----------|----------|--------|
| **Gossip-протокол** | Эпидемическая рассылка с TTL=3 | Работает (для 3+ узлов) |
| **Дельта-синхронизация** | Только изменившиеся слои | Работает |
| **Троттлинг** | Не чаще 5 секунд | Работает |

### Маршрутизация сообщений

| Механизм | Описание | Статус |
|----------|----------|--------|
| **Gossip** | Рассылка всем подписанным узлам | Работает |
| **Форвардинг** | Пересылка через соседей с TTL | Работает |
| **Sphinx** | Слоистое шифрование, 2 relay + получатель | Реализован (v2.0.1) |
| **Onion Routing (полный)** | Цепочка из 3+ пиров | В планах (v2.0+) |

## Протоколы

### Основной протокол: `/sbicore/1.0.0`

Используется для обмена сообщениями между узлами.

Формат:
MSGID:текст сообщения

text

### Протокол синхронизации: `/sbicore/sync/1.0.0`

Используется для обмена слоями нейросети.

Формат (JSON):

```json
{
  "ttl": 3,
  "delta": [
    {"index": 0, "data": [0.1, 0.2, ...]},
    {"index": 1, "data": [0.3, 0.4, ...]}
  ]
}
Жизненный цикл узла
Запуск — генерация RSA (PeerID) + Ed25519 (подпись) + X25519 (E2E)

Загрузка состояния — из state_nodeX.json

Подключение к сети — mDNS + DHT + bootstrap

Синхронизация слоёв — gossip-протокол

Обмен сообщениями — форвардинг

Обучение — каждый узел учится локально

Отказоустойчивость
Нет единой точки отказа — любой узел может упасть, сеть продолжит работать

Селф-хилинг — если relay-пир падает, соседи перенимают его обязанности (в планах)

Автономность — mDNS работает без интернета

Безопасность
Шифрование: Noise (встроено в libp2p)

Аутентификация: PeerID — RSA (до v2.0.6), Ed25519 — подпись (v1.24)

E2E-шифрование: X25519 + box.Seal (v1.24)

Защита от атак Сивиллы: этический хеш + вес узлов

Ограничения текущей версии
DHT не тестировался в WAN — в Docker за NAT не работает

Gossip для 3 узлов = broadcast — эффект будет виден при 10+ узлах

Onion Routing (полный) — в планах. Sphinx (v2.0.1) — реализован.
