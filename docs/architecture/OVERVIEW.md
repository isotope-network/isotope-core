# Архитектура ISOTOPE

## Обзор

ISOTOPE — децентрализованный P2P-мессенджер
с нейросетевым этическим фильтром,
анонимной маршрутизацией и адаптивной маскировкой трафика.

    [Flutter App] ←→ REST/WebSocket ←→ [Узел ISOTOPE] ←→ P2P-сеть ←→ [Другие узлы]

## Ключевые компоненты

### 1. P2P-сеть (libp2p)

- **Транспорт:** TCP + WebSocket + TLS
- **Обнаружение:** mDNS (локалка) + DHT Kademlia (WAN)
- **Синхронизация:** Gossip-протокол (TTL=3, fanout=√N)
- **Маршрутизация:** Onion Routing (3+ пира в цепочке)
- **Маскировка:** WebSocket + TLS (выглядит как HTTPS)
- **Приоритеты:** Priority Gossip — TTL зависит от веса узла

### 2. Этический движок (нейросеть)

- **Вектор:** 100 измерений (VectorDim = 100)
- **Слои:** растут каждые 20 сообщений
- **Обучение:** градиентный спуск, lr = 0.01 × вес
- **Контекст:** поиск похожих (косинусное расстояние > 0.7)
- **Хеш:** семь универсальных заповедей

### 3. Память

- **Тип:** взвешенная, FIFO с архивом
- **Вес:** от этического хеша + preHash/antiHash + оценки
- **Старение:** -0.01/час
- **Архивация:** вес < 0.15
- **Удаление:** вес < 0.1

### 4. API

- **REST:** /send, /messages, /status, /health, /feedback
- **WebSocket:** /ws (двунаправленный канал)
- **Фильтры:** /setprehash, /setantihash

### 5. Безопасность

- **E2E-шифрование:** Ed25519
- **Анонимность:** Onion Routing (свой, без Tor)
- **Маскировка:** WebSocket + TLS (выглядит как HTTPS)

---

## Принципы

1. **Децентрализация.** Нет сервера, нет единой точки отказа
2. **Этический иммунитет.**
   Сеть отличает добро от зла математически
3. **Самообучение.** Сообщество учит сеть через оценки
4. **Приватность.**
   Данные не покидают устройство без согласия
5. **Неуязвимость.**
   Сеть нельзя заблокировать, отключить или взломать

## Масштаб и иммунитет

Иммунная система ISOTOPE включается при 15+ узлах.
До этого сеть работает как защищённый P2P-протокол.
