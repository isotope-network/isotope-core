# ISOTOPE — Инфраструктурный слой для экономики данных

**Спрашивай, не раскрывая. Отвечай, не раскрывая.**

ISOTOPE — это архитектура для обмена данными, в которой источник информации не раскрывается, а ответ подтверждается сетью.

---

## Как устроена архитектура

В основе ISOTOPE лежит единый паттерн: **запрос-ответ без раскрытия**.

Участник задаёт вопрос. Сеть находит узлы, способные ответить. Ответ приходит без доступа к данным, без раскрытия источника, без идентификации отвечающего.

- «Был ли у клиента дефолт за последние 2 года?» → Ответ: «Нет»
- «Какой коэффициент сердечно-сосудистого риска?» → Ответ: «0.88»
- «Этот сертификат действителен?» → Ответ: «Нет»

Данные не передаются. Личность не раскрывается. Имеет значение только ответ.

## Принципы архитектуры

**Этический хеш.** Цифровое ДНК сети. Семь заповедей, преобразованные в 100-мерный вектор. Каждое сообщение сравнивается с эталоном. Ближе к эталону — дольше живёт. Дальше — затухает. Это не цензура. Это иммунная система.

**Взвешенная память.** Сообщения не удаляются по команде. Они получают вес. Лайки поднимают вес. Дизлайки опускают. Время размывает даже сильные сигналы. Когда вес падает ниже порога — данные уходят в архив. Ниже — удаляются навсегда. Сеть дышит: важное остаётся, случайное уходит, вредное отторгается.

**Коллективное обучение.** Нейросеть учится на оценках сообщества. Каждый лайк и дизлайк сдвигает веса. Сеть не программируется — она обучается. Без модератора. Без словарей запрещённых слов.

**Децентрализация.** Нет сервера. Нет компании. Нет единого центра. Узлы находят друг друга через mDNS, DHT, Bluetooth. Сеть живёт, пока жив хотя бы один узел.

## Свойства архитектуры

**Иммунитет включается с масштабом.**

| Узлов | Свойство |
|-------|----------|
| 2-3 | Защищённый P2P-канал. Иммунитета нет |
| 5-10 | Ранний консенсус. Видны выбросы |
| 15-20 | Включается иммунитет. Веса начинают работать |
| 50+ | Стабильный иммунитет. Сговор не влияет |
| 100+ | Неостановимая сеть. Селф-хилинг |

Это не недостаток. Это архитектурное свойство. Масштаб включает иммунитет.

**Четыре слоя архитектуры.**

| Слой | Суть |
|------|------|
| Технический | Протокол запроса-ответа без раскрытия |
| Философский | Этика, встроенная в протокол |
| Бизнес | Рынок доверия без посредников |
| Прикладной | Мессенджер как живая демонстрация |

## Что вытекает из архитектуры

Архитектура позволяет любые взаимодействия, где нужны децентрализация, этическая фильтрация и доверие без посредников.

**Готовые сценарии.** Решите конкретную задачу за один день.

| Сценарий | Проблема | Минимум узлов |
|----------|---------|---------------|
| Проверка сертификатов | Поддельные сертификаты, долгие проверки | 3 |
| Кредитный чек | Клиенты уходят, не желая раскрывать историю | 3-5 |
| Анонимное голосование | Недоверие к результатам, страх раскрытия | 20-30 |
| Антифрод | Деньги уводят, пока идёт проверка | 5-10 |
| Консультация врачей | Нельзя передать данные пациента коллеге | 2-5 |

[Подробнее: 10 доменов, 30+ сценариев →](docs/USE_CASES.md)

**Два вектора роста.**

| Вектор | Продукт | Аудитория | Метрика |
|--------|---------|-----------|---------|
| Enterprise | Протокол + коммерческая лицензия | Банки, страховые, государства | Узлы, запросы, контракты |
| Community | Мессенджер (open source) | Люди, разработчики | Установки, форки, контрибьюторы |

Оба вектора питают друг друга. Мессенджер доказывает, что протокол работает. Протокол даёт мессенджеру неуязвимость.

## Мессенджер: точка входа в сеть

Пользователь устанавливает мессенджер ISOTOPE. Его узел автоматически участвует во всех сценариях — не спрашивая, не отвлекая.

Пока пользователь общается с друзьями, его узел:
- Проверяет сертификаты для поставщиков
- Помогает банкам ловить мошенников
- Участвует в анонимных научных опросах
- Подтверждает голоса в локальных сообществах

Раз в день — одно уведомление:

> «Ваш узел сегодня: 12 сертификатов проверено, 1 мошенник пойман, 3 научных запроса. Заработано: 2.8 ISOTOPE.»

**Формула:** Установил мессенджер. Общаешься. Сеть работает. Токены капают.

## Быстрый старт

### Требования
- Docker и Docker Compose
- Go 1.21+ (для сборки из исходников)
- Flutter 3.x (для мобильного приложения)

### Запуск узла

    git clone https://github.com/isotope-network/isotope-core.git
    cd isotope-core
    docker compose build --no-cache
    docker compose up -d

Узлы:
- http://localhost:8081 (узел 1)
- http://localhost:8082 (узел 2)
- http://localhost:8083 (узел 3)

## Статус

**v1.5 — стабильная.**
