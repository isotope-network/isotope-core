# ISOTOPE — инфраструктура для этичного, неуязвимого, самообучающегося обмена данными и ИИ

**Спрашивай, не раскрывая. Отвечай, не разглашая.**

ISOTOPE — это инфраструктура, которая объединяет
обмен данными, распределённый ИИ и общение людей
в одной децентрализованной сети.

---

## Не Tor. Не Signal. Не Telegram.

**Tor** скрывает, кто ты. ISOTOPE скрывает, что ты говоришь.

**Signal** защищает содержимое. ISOTOPE защищает сам факт разговора.

**Telegram** даёт удобство за плату. ISOTOPE даёт свободу без цены.

ISOTOPE — это не мессенджер. Не протокол. Не бизнес.
Это инфраструктура, где человек — не пользователь, а узел.
Где доверие — не проверка, а взаимодействие.
Где свобода — не обещание, а архитектура.

---

## Три столпа ISOTOPE

**Данные.**
Запрос-ответ без раскрытия.
Банки, страховые, больницы, поставщики обмениваются
ответами на вопросы, не передавая сами данные.

**ИИ.**
Распределённый инференс.
Облегчённые модели работают на узлах сети.
Простые запросы обрабатываются ближайшим узлом.
Сложные — уходят в дата-центр.
Каждая модель проходит этический паспорт перед загрузкой.

**Люди.**
Мессенджер как точка входа.
Общение без цензуры, блокировок и слежки.
Узел пользователя автоматически участвует в работе сети.

Фундамент — **Сеть**:
P2P, этический хеш, иммунитет, самообучение.

---

## Как устроена архитектура

В основе ISOTOPE лежит единый паттерн:
**запрос-ответ без раскрытия**.

Участник задаёт вопрос.
Сеть находит узлы, способные ответить.
Ответ приходит без доступа к данным,
без раскрытия источника,
без идентификации отвечающего.

- «Был ли у клиента дефолт за последние 2 года?» → Ответ: «Нет»
- «Какой коэффициент сердечно-сосудистого риска?» → Ответ: «0.88»
- «Этот сертификат действителен?» → Ответ: «Нет»
- «Переведи текст» → Ближайший узел с языковой моделью отвечает

Данные не передаются. Личность не раскрывается.
Имеет значение только ответ.

## Принципы архитектуры

**Этический хеш.**
Цифровое ДНК сети.
Семь универсальных заповедей,
преобразованные в 100-мерный вектор.
Каждое сообщение и каждый ИИ-ответ
сравниваются с эталоном.
Ближе к эталону — дольше живёт.
Дальше — затухает.
Это не цензура. Это иммунная система.

**Взвешенная память.**
Сообщения не удаляются по команде.
Они получают вес.
Лайки поднимают вес. Дизлайки опускают.
Время размывает даже сильные сигналы.
Когда вес падает ниже порога — данные уходят в архив.
Ниже — удаляются навсегда.
Сеть дышит: важное остаётся,
случайное уходит, вредное отторгается.

**Коллективное обучение.**
Нейросеть учится на оценках сообщества.
Каждый лайк и дизлайк сдвигает веса.
Сеть не программируется — она обучается.
Без модератора. Без словарей запрещённых слов.

**Децентрализация.**
Нет сервера. Нет компании. Нет единого центра.
Узлы находят друг друга через mDNS, DHT, Bluetooth.
Сеть живёт, пока жив хотя бы один узел.

**Приватность по умолчанию.**
Каждое сообщение защищено сквозным шифрованием.
Relay видит только шифротекст.
Ключ есть только у отправителя и получателя.

**Эмерджентное доверие.**
Проверен — это сигнал, не пропуск.
Вес нарабатывается, не доказывается.
Доверие растёт из взаимодействия, не из авторитета.

**Право на забвение.**
Сообщение не «удаляется». Оно отпускается.
Как отпускают прошлое — без сожаления.
Забвение — это не потеря. Это освобождение.

**Право на тишину.**
Короткие TTL (10 сек – 1 мин) — запрет скриншотов.
Это не «я не хочу, чтобы ты видел».
А «я хочу, чтобы это осталось между нами и исчезло».

**Тихий отказ.**
Удаление контакта — это не блокировка. Это тихий отказ.
Блокировка — принуждение. Тишина — свобода.

**Единый источник истины.**
Если поле выводимо из Message — оно в Message.
Status, ReadLocally, Refs — всё в Message.
Никаких вторых источников. Никаких расхождений.

**Offline-очередь — ответственность отправителя.**
VPS не буферизует. Отправитель держит pending до [DELIVERED].
Когда получатель появляется — отправитель переотправляет.
VPS — курьер, не хранилище.

**Миграции обязательны.**
Старые данные не теряются.
messageStatus → Message.Status.
_readSent → ReadLocally.
Каждая миграция логируется.

## Свойства архитектуры

**Иммунитет включается с масштабом.**

| Узлов | Свойство |
|-------|----------|
| 2-3 | Защищённый P2P-канал. Иммунитета нет |
| 5-10 | Ранний консенсус. Видны выбросы |
| 15-20 | Включается иммунитет. Веса начинают работать |
| 50+ | Стабильный иммунитет. Сговор не влияет |
| 100+ | Неостановимая сеть. Селф-хилинг |

Это не недостаток. Это архитектурное свойство.
Масштаб включает иммунитет.

**Весовая модель доступа.**
Вес узла — универсальный пропуск.

| Вес | Права |
|-----|-------|
| 0–0.3 | Читать (тизер) |
| 0.3–0.5 | Полный доступ |
| 0.5–0.7 | Комментировать, модерировать |
| 0.7–1.0 | Голосовать, relay, реплики |

## Что вытекает из архитектуры

Архитектура позволяет любые взаимодействия,
где нужны децентрализация,
этическая фильтрация
и доверие без посредников.

**Готовые сценарии.**
Решите конкретную задачу за один день.

| Сценарий | Проблема | Минимум узлов |
|----------|---------|---------------|
| Проверка сертификатов | Поддельные сертификаты, долгие проверки | 3 |
| Кредитный чек | Клиенты уходят, не желая раскрывать историю | 3-5 |
| Анонимное голосование | Недоверие к результатам, страх раскрытия | 20-30 |
| Антифрод | Деньги уводят, пока идёт проверка | 5-10 |
| Консультация врачей | Нельзя передать данные пациента коллеге | 2-5 |
| Простые запросы к ИИ | Серверы ИИ перегружены в пиковые часы | 5-10 |

## Мессенджер: точка входа в сеть

Пользователь устанавливает мессенджер ISOTOPE.
Его узел автоматически участвует во всех сценариях —
не спрашивая, не отвлекая.

Пока пользователь общается с друзьями, его узел:
- Проверяет сертификаты для поставщиков
- Помогает банкам ловить мошенников
- Отвечает на простые ИИ-запросы
- Участвует в анонимных научных опросах
- Подтверждает голоса в локальных сообществах

Раз в день — одно уведомление:

> «Ваш узел сегодня: 12 сертификатов проверено,
> 3 ИИ-запроса обработано,
> 1 мошенник пойман.
> Заработано: 2.8 ISOTOPE.»

**Формула:**
Установил мессенджер. Общаешься.
Сеть работает. Токены капают.

## Быстрый старт

### Требования
- Docker и Docker Compose
- Go 1.21+
- Flutter 3.x

### Запуск узла

    git clone https://github.com/isotope-network/isotope-core.git
    cd isotope-core
    docker compose build --no-cache
    docker compose up -d

Узлы:
- http://localhost:8081 (узел 1)
- http://localhost:8082 (узел 2)
- http://localhost:8083 (узел 3)
- http://localhost:8084 (узел 4)
- http://localhost:8085 (узел 5)

### Сборка из исходников

    go build -o isotope-node ./node/main
    ./isotope-node --config config.json

### Использование как библиотека

import core "sbimain"

config := core.Config{
    NodeID:     "node-1",
    Port:       9001,
    Transports: []string{"ws"},
}

node := core.NewNode(config)
core.InitP2P(node)
core.StartHTTP(node)
defer core.Stop(node)
